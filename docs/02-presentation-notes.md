# نکات ارائه پروژه

## معرفی کوتاه

این پروژه یک کارتابل ساده نامه است. کاربر وارد سامانه می‌شود، برای کاربر دیگر نامه می‌فرستد و نامه‌های دریافتی و ارسالی خود را مشاهده می‌کند.

## فایل‌هایی که باید بشناسید

- `backend/app/main.py`: مسیرهای API و منطق ارسال و دریافت نامه
- `backend/app/models.py`: مدل‌های دیتابیس
- `backend/app/security.py`: هش رمز و ساخت توکن
- `backend/app/database.py`: اتصال به دیتابیس و ساخت کاربران نمونه
- `frontend/app.js`: ارتباط صفحه با API
- `docker-compose.yml`: اجرای سه بخش پروژه

## سؤال‌های رایج

### JWT چیست؟

توکنی است که بعد از ورود ساخته می‌شود. بک‌اند با بررسی آن متوجه می‌شود درخواست مربوط به کدام کاربر است.

### چرا رمز عبور مستقیم ذخیره نشده است؟

رمز به صورت هش‌شده ذخیره شده تا مقدار اصلی آن داخل دیتابیس دیده نشود.

### ORM چیست؟

ORM کمک می‌کند جدول‌های دیتابیس با کلاس‌های Python تعریف شوند. در این پروژه SQLAlchemy این کار را انجام می‌دهد.

### رابطه کاربر و نامه چیست؟

هر نامه یک فرستنده و یک گیرنده دارد. هر کاربر می‌تواند چند نامه ارسال و چند نامه دریافت کند.

### Dockerfile و Docker Compose چه فرقی دارند؟

Dockerfile روش ساخت یک Image را مشخص می‌کند. Docker Compose چند سرویس را با تنظیمات مشترک اجرا می‌کند.

### Volume چه کاربردی دارد؟

باعث می‌شود با حذف و ساخت دوباره Containerها، دیتابیس و پیوست‌ها باقی بمانند.

### Nginx چه کاری انجام می‌دهد؟

فایل‌های فرانت‌اند را نمایش می‌دهد و درخواست‌های `/api` را به بک‌اند می‌فرستد.

### چرا نام فایل روی سرور تغییر می‌کند؟

برای جلوگیری از تکراری‌شدن نام فایل‌ها، هر فایل با یک نام یکتا ذخیره می‌شود. موقع دانلود، نام اصلی فایل به کاربر برگردانده می‌شود.

### چگونه از دسترسی غیرمجاز به نامه جلوگیری شده است؟

بک‌اند قبل از نمایش نامه یا دانلود پیوست بررسی می‌کند کاربر فعلی فرستنده یا گیرنده همان نامه باشد.

## سناریوی نمایش

1. با حساب `ali` وارد شوید.
2. برای `sara` یک نامه همراه فایل بفرستید.
3. از حساب خارج شوید.
4. با `sara` وارد شوید.
5. نامه را در دریافتی باز کنید و فایل را دانلود کنید.
6. وضعیت خوانده‌شدن نامه را نشان دهید.
